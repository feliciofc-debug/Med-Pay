fix(alembic): encurta revision_id da migration 018 e torna idempotente

O Render estava falhando ao subir o deploy com:
  psycopg2.errors.StringDataRightTruncation
  value too long for type character varying(32)
  [SQL: UPDATE alembic_version SET version_num='018_beneficiario_conta_verificada'
        WHERE alembic_version.version_num = '017_user_cliente_id']

Causa: revision_id '018_beneficiario_conta_verificada' tinha 33 chars,
mas alembic_version.version_num e' VARCHAR(32). Como o erro acontece
DEPOIS do ALTER TABLE rodar, o banco do Render ficou em estado
inconsistente: colunas criadas mas alembic_version preso em 017.

Correcao:
- revision_id encurtado: '018_benef_conta_verif' (21 chars)
- Migration agora usa SQL bruto com ADD COLUMN IF NOT EXISTS
  (idempotente) — funciona tanto em ambientes novos quanto no
  Render que ja tem as colunas criadas parcialmente.
- Downgrade tambem usa DROP COLUMN IF EXISTS.

Resultado esperado:
  No proximo deploy, alembic detecta versao 017, tenta subir pra 018.
  Os ALTER TABLE silenciosamente nao fazem nada (colunas ja existem),
  e UPDATE alembic_version salva '018_benef_conta_verif' sem estourar
  o limite de 32 chars.
